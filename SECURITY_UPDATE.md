## 🚀 Инструкции по развертыванию

### Шаг 1: Проверка переменных окружения

Проверьте ваш `.env` файл. Теперь обязательны:

```env
JWT_SECRET=<ваш_512_битный_ключ>
ENCRYPTION_KEY=<ваш_256_битный_ключ>
```

✅ Ключи уже сгенерированы и добавлены в .env

### Шаг 2: Миграция существующих SMTP паролей

Если у вас уже есть отправители в базе данных, запустите скрипт миграции:

```bash
node scripts/encryptExistingPasswords.js
```

Этот скрипт:
- Найдет все незашифрованные пароли
- Зашифрует их с помощью AES-256
- Обновит записи в БД
- Выведет отчет о миграции

**⚠️ ВАЖНО:** Запустите этот скрипт ОДИН РАЗ перед запуском сервера!

### Шаг 3: Перезапуск сервера

```bash
npm run dev
# или
npm start
```

При запуске вы увидите проверки:
- ✅ JWT_SECRET установлен и валиден
- ✅ ENCRYPTION_KEY установлен
- ✅ Миграции БД выполнены

Если что-то не так, сервер не запустится и покажет ошибку.

## 🔐 Что изменилось для разработчиков

### Работа с SMTP паролями

**Раньше:**
```javascript
// Пароль хранился в открытом виде
const sender = await db.getSender(id, userId);
console.log(sender.password); // plain text
```

**Теперь:**
```javascript
// Пароль автоматически расшифровывается при чтении
const sender = await db.getSender(id, userId);
console.log(sender.password); // расшифрованный пароль (готов к использованию)

// При сохранении пароль автоматически шифруется
await db.addSender({ ...senderData, password: 'plain-password' }, userId);
// В БД сохраняется: "a1b2c3...iv:encrypted_data"
```

### Rate Limiting для login

**Изменения:**
- Теперь максимум 5 попыток входа за 15 минут
- Успешный вход не считается попыткой
- После превышения лимита: HTTP 429

**Тестирование:**
```bash
# Попытайтесь войти 6 раз с неверным паролем
# 6-я попытка вернет ошибку rate limit
```

### Валидация файлов

**Изменения:**
```javascript
// Теперь при импорте проверяется:
// 1. Размер файла (макс 10MB)
// 2. MIME-тип (только Excel)
// 3. Если не прошло - HTTP 400 с описанием ошибки
```

## ⚠️ Важные замечания

### Для Production

1. **JWT_SECRET и ENCRYPTION_KEY**
   - Никогда не коммитьте .env в git
   - Используйте разные ключи для dev/prod
   - Храните ключи в безопасном месте (Vault, AWS Secrets Manager)

2. **HTTPS обязателен**
   - В production всегда используйте HTTPS
   - Иначе httpOnly cookies могут быть перехвачены

3. **Backup ключей**
   - Сохраните ENCRYPTION_KEY в безопасном месте
   - Без него вы не сможете расшифровать существующие пароли
   - При потере ключа придется пересоздавать всех отправителей

4. **Миграция паролей**
   - Запустите скрипт миграции перед деплоем
   - Проверьте, что все пароли зашифрованы
   - Старые незашифрованные пароли будут работать, но с предупреждением

### Обратная совместимость

Система поддерживает старые незашифрованные пароли:
- При чтении: если пароль не содержит ":", он считается незашифрованным
- Выводится предупреждение в консоль
- Рекомендуется пересохранить такие записи
